# Decisions

Architecture decisions, ADR-style: context, the choice, why, and — where it matters —
the *seam* deliberately left open for a later stage. Read these when you're about to
change something, to check you're not welding shut a planned extension.

# Core architecture

* [trust-boundary](/decisions/trust-boundary.md) - Agents cite but never author facts, mint currency, or actuate. Three privileged powers stay in trusted infrastructure.
* [thin-trusted-infra](/decisions/thin-trusted-infra.md) - Relax the powers toward public functions + signed artifacts + bounded devices; the one irreducible trusted thing is the currency ledger (double-spend).
* [llm-heavy-deliberation](/decisions/llm-heavy-deliberation.md) - Thin BDI: the LLM drives deliberation; the formal layer becomes load-bearing, not optional.
* [deterministic-bid](/decisions/deterministic-bid.md) - The bid number is code; the LLM only produces the justification. Rhetoric can't move the number.
* [english-vs-formal](/decisions/english-vs-formal.md) - English for what's contested, formal (RDF/SHACL) for what's trusted.
* [agent-centric-epistemics](/decisions/agent-centric-epistemics.md) - Judgment, private data, and perception belong to the agent; infra is thin honest mechanism; author by stake; disclose need-to-know; observe via sovereign.

# Identity & authorization

* [authn-authz-capabilities](/decisions/authn-authz-capabilities.md) - Cert = who you are (durable); signed capability grant / JWT = what you may do now (ephemeral). Revoke only on provable violation.
* [two-worlds-were-one](/decisions/two-worlds-were-one.md) - `society` and `simulation` differed by 45 lines of ~230 with byte-identical beliefs, so the one that needs no hardware stayed. Keeping the flashed-board property meant `simulation` adopting `sensing`'s device ids AND dropping its `sim/` prefix: matching ids alone would have made the test green and the property false, since the usernames are world-independent by construction and the ACL would still have denied the board its first publish. The prefix was safe to drop because each world runs its own broker; what it cost is that simulated traffic is no longer obvious from the topic. The test compares grants now, as a subset — a stand-in needs one grant a real probe does not.
* [a-stream-is-a-thing](/decisions/a-stream-is-a-thing.md) - A channel is derived from the topics devices already state, one node per distinct topic, its IRI a FUNCTION of that string — because `$given` excludes the derived graph, so two packages agree on a node only by computing it independently. The codec moves off the sensor onto the stream, which closes a hole that really was open: accepted on main, refused now. The first measurement of that hole was wrong twice over, which is the more useful half. Moving the credential onto the board did not follow — it collides with one flashed board working in either world.
* [the-wire-is-ours-and-it-has-two-levels](/decisions/the-wire-is-ours-and-it-has-two-levels.md) - A credential and a codec are both facts about the wire and not about the same part of it: a transport and an encoding vary independently, so the credential is the connection's and the encoding is the stream's. SOSA gives the physical decomposition and SSN the procedural one, and the spec has NO guidance on transmission — so the wire is ours. Scaling was never on it at all; it is the measurand's. A simulated world correctly has no platforms, and a channel is still a string, which is the board's defect one level down.
* [a-stand-in-reports-what-its-world-says-it-does](/decisions/a-stand-in-reports-what-its-world-says-it-does.md) - Everything for a board reporting several properties was built and no such message had ever been published by anything: the real firmware sends three values and has never been compiled here, the stand-in sent one, and the unit test fed a payload straight to handle(). The stand-in now reports a value per property at the pointers its world declares, each drifting in its own range, and water moves only the one a litre is worth something to. Two shapes had to stop assuming every value is a fraction and every device holds a credential — both already disproved by the hardware world. Running it put a real two-value message on a real broker and two observations in the store, and found a belief volume older than the namespace sweep that no gate can see.
* [their-descriptions-are-our-fixtures](/decisions/their-descriptions-are-our-fixtures.md) - Whether a standard description can be deployed without editing was argued from first principles and the arguments were wrong both ways, so the W3C's own DHT22 examples are vendored and measured instead. A deployment description needs no editing AT ALL; a device description is missing exactly the four facts a vendor could not know, which is the part/deployment boundary. The two relaxations were both spelling — legacy http schema.org and QUDT 1.1 — and the one thing still refused is their illustrative reading, which stays refused because completing it would fabricate provenance for a reading nobody took.
* [an-observation-says-how-it-was-made](/decisions/an-observation-says-how-it-was-made.md) - A reading carries `sosa:usedProcedure` now, because whether silence means a late board or a quiet one was recoverable only by joining an observation back to its sensor. The three modes are renamed to read as procedures rather than states — a Procedure is a plan — each keeping its mode word so the pairing with its capability still reads. The rename crossed six spellings, and the dangerous one had left the process: the simulator's environment was built by lowercasing the IRI, so a self-clocked stand-in would have quietly kept an interval instead, with nothing failing.
* [one-word-for-one-relation](/decisions/one-word-for-one-relation.md) - A subclass axiom is a claim that our term means MORE, so where nothing checks the difference it is a synonym with an unenforced comment. mc:carries, perception:Sensor, actuation:Actuator and perception:seconds went, each trading a term for a rule that is checked. ag:Device, perception:senseMode and review:Revision stayed, and the test that emerged is not whether a standard has a similar word but whether it is asking the same QUESTION — SOSA models the instrument and the observation, we model the agent dealings with them.
* [what-is-true-of-a-part-is-true-of-every-one-of-them](/decisions/what-is-true-of-a-part-is-true-of-every-one-of-them.md) - A datasheet fact written on dht11:Dht11 entailed nothing about any DHT11, because a class-level triple is PUNNING. It is an owl:hasValue restriction now and the closure materialises it, so the sovereign observes the capability on the device the wiring declares without anyone writing it there. Describing at class level was the idea and plain OWL was enough — a metamodel is for saying things ABOUT a classification, and this says something about members. What does not change is the boundary: an agent is never given `a dht11:Dht11`, so an agent may know a part's properties and not its identity. It also found the guard on all this had asserted nothing for two PRs.
* [a-part-is-described-once-and-fitted-many-times](/decisions/a-part-is-described-once-and-fitted-many-times.md) - W3C's SSN example describes one serial-numbered DHT22 and every fact in it is about that unit; we ship a package for a MODEL, so the DHT11's two channels, its procedures at three levels and its per-channel datasheet figures are stated on classes and reach devices by entailment. Building it found ssn:implements had been punned since it was introduced — the only subject with that predicate anywhere was the class itself, so no device in any world had been said to do anything. A capability is one shared individual and takes owl:hasValue; a channel is per-unit, takes owl:someValuesFrom, entails nothing, and is enforced by a shape instead. What a channel OBSERVES stays out, because that would import the domain vocabulary into a part.
* [a-species-is-described-once-and-planted-many-times](/decisions/a-species-is-described-once-and-planted-many-times.md) - Zamioculcas zamiifolia gets its own package, shaped exactly like a part's: a species is a model and the pots are units, so its care is stated on the class and reaches each pot by owl:hasValue — planting one is one triple. It states TWO ranges because SSN has both words and this plant needs them, the gap being asymmetric: it returns from bone dry and not from a rotted rhizome. Answers the structural question that prompted it too — vocabulary packages already ARE capability-shaped, found the same way with the same four files, and the only difference is Python they have no use for.
* [a-board-says-what-it-can-honour](/decisions/a-board-says-what-it-can-honour.md) - The third source ranges() has always named — constitution, mandate, hardware — existed only in a docstring, so an agent could commit to a cadence its board would never keep and a healthy board read as a quiet one. A device states an ssn-system:Frequency, whose definition is a TIME and not a rate and carries "under the defined Conditions" in itself, so mains and battery are two capabilities rather than one number with a caveat. Borrowed not imported, which cost one axiom: sosa:Sensor rdfs:subClassOf ssn:System is SSNs and nothing here loaded it, so the module reached nothing at all.
* [a-board-is-a-platform](/decisions/a-board-is-a-platform.md) - The board three sensors share was not a node, so every fact about it was repeated per sensor or recovered by comparing topic strings. It is a sosa:Platform now, hosting its parts and they their channels — which is why SOSA lets a Platform host Platforms. mc:carries turns out to BE sosa:hosts and is declared a subproperty of it, the first subPropertyOf axiom here and the one the closure was built for. The society states its own hosting because an agent is never given the wiring, and a test holds the two to agreeing. The codec did NOT move onto the platform: two worlds have nine sensors and no platform between them.
* [bytes-become-a-quantity-in-stages](/decisions/bytes-become-a-quantity-in-stages.md) - The codec and the scaling become package trees beside transports, each a family whose serving member is DERIVED onto the sensor at genesis rather than searched for at boot; the pointer stays a function, because RFC 6901 works over any tree. The trees turn out to be one mechanism split by BEARER and not by importance — rule 2 says nothing about who bears a capability, so what differs is only that these land on a binding rather than on an agent. Named scaling and not calibration, because calibration is the PROCEDURE that finds the numbers a scaling then applies. Scaling is also where a number acquires a unit: three sensors state QUDT IRIs, borrowed and not imported, and no number moved.
* [a-reading-is-one-value-so-it-is-pointed-at](/decisions/a-reading-is-one-value-so-it-is-pointed-at.md) - Where a sensor's value sits in a shared payload is a JSON Pointer (RFC 6901) — it identifies exactly ONE value, which is what a reading is; JSONPath (RFC 9535) returns a nodelist and would need a collapse rule invented on top of a standard. Absent means `/value`, so no existing sensor states one. Getting a quantity off a wire is three stages — codec, pointer, calibration (#26) — and a pointer is indifferent to both neighbours, which is why deferring them cost nothing. A cadence turned out to belong to the board rather than to a property.
* [one-agent-many-sensors](/decisions/one-agent-many-sensors.md) - Three of the four combinations work, measured rather than assumed. The two that do not are both triggered by giving one subject a second KIND of sensor: an observation keyed by subject alone, and sensors that the derivation splits but the runtime does not.
* [wokwi-drafts-it-the-world-ratifies-it](/decisions/wokwi-drafts-it-the-world-ratifies-it.md) - Importing a diagram DRAFTS a stand and never becomes its source: the mapping is invertible, but Wokwi recovers the shape of a wiring and none of its meaning. Bidirectional sync was refused rather than deferred, because a world synced from a drawing has nothing left to refuse.
* [pins-and-wires](/decisions/pins-and-wires.md) - The core vocabulary splits into a stand plus a package per protocol and per part; a pin assignment becomes a pin, a role and a wire. A pin is metal, a role is abstract, and the wire is what people get wrong — which is what finally made the rail-voltage fault refusable.
* [repository-layout](/decisions/repository-layout.md) - One convention across six Python trees, one distribution instead of two, and a packaging boundary replaced by a test and an import contract — both verified by breaking them. Why capabilities live inside the agent and the vocabulary does not.
* [one-tree-and-one-mechanic](/decisions/one-tree-and-one-mechanic.md) - Two package systems looked alike and lived apart, split by who loads the Python — which is invisible in a listing and left Package.kind saying "vocabulary" for eleven packages that could not be told apart. One tree now, packages/<family>/<name>/, with the family read off the path and declared nowhere. The cost is stated rather than hidden: the layout no longer shows which Python a runtime loads, so lint-imports and the Containerfile carry that boundary alone. The move also cost 143 tests silently — a glob that did not empty, merely stopped covering what it was named for.
* [a-package-may-test-itself](/decisions/a-package-may-test-itself.md) - A package carries its own tests as plain test_*.py files beside the code, not a tests/ subdirectory — which collides on module basenames and reads as a subpackage. Only one file qualified and the motivating count was wrong (17, not 29): eleven "reporting unit tests" take a fixture that builds a real agent, which the marker list did not name. The load-bearing change is the gate: a test inside a package is collected by neither `pytest tests` nor a bare `pytest`, so testpaths names both roots and a guard asserts the link.
* [series-and-bus-isolation](/decisions/series-and-bus-isolation.md) - A bucket and a scoped token per agent, and per-principal broker credentials whose topics are derived from the same wiring that derives capability. Closes the two holes where-the-belief-base-lives left open.

# Economy

* [single-wallet-metabolic-cost](/decisions/single-wallet-metabolic-cost.md) - One wallet for water and compute; thinking costs, so bounded rationality is priced in.
* [strategic-supplier](/decisions/strategic-supplier.md) - The supplier is a genuine seller with costs and a reserve price (Design B), not a stake-free utility.
* [the-lot-is-the-hosts-standing-offer](/decisions/the-lot-is-the-hosts-standing-offer.md) - A round is triggered by a band and sized by a fixed host belief, so its size has nothing to do with what anyone needs — the host is deliberately blind to quantity until bids are in. Measured: half the lot can be wanted by agents none of whom can convene a round.
* [clearing-as-validator](/decisions/clearing-as-validator.md) - The scarce side runs the auction; clearing is a thin stake-free notary that checks integrity and co-signs the trade before settlement.

# Belief base

* [two-store-beliefs](/decisions/two-store-beliefs.md) - InfluxDB owns the series; Fuseki owns citable current-state. Joined by plant URI, never federated.
* [world-graph](/decisions/world-graph.md) - No config file: the world graph holds only topology (public, versioned, stated once); desire, limits, cadence and prices are each agent's private beliefs. Agent/Sensor/Actuator become first-class.
* [capability-modules](/decisions/capability-modules.md) - Code reads T-Box terms, never instances. A capability is an ontology module + shapes + derivation rules + code; capabilities are derived from hardware at genesis, and each agent is its own process knowing only its id. (Superseded on packaging by capability-packages.)
* [who-holds-the-clock](/decisions/who-holds-the-clock.md) - Perception is three capabilities on one axis: Polling (the agent asks each time — declared, reserved, no hardware for it), Subscribing (the agent states an interval the device keeps — what the ESP32 does), Listening (the device announces). What was called Polling was Subscribing all along.
* [a-belief-is-a-pick-within-a-range](/decisions/a-belief-is-a-pick-within-a-range.md) - A belief is a point chosen inside a range, not a constant: what genesis wrote is the first pick and the constraints (world, sensor, self) are the bound. Which terms may be re-picked is one triple in the owning package's ontology; a rule is SPARQL, not code; legitimacy is the boot check re-run. A summary is a belief and a reading is a measurement, so history stays in Influx.
* [the-range-is-the-plants-and-the-pick-is-the-agents](/decisions/the-range-is-the-plants-and-the-pick-is-the-agents.md) - Desire was already in the belief base and unnamed — water:hasTarget is commented "Desire" — but it answered to nothing, so 0.55 validated exactly as well as 0.95. A plant now states the range it needs in the world, in SSN's OperatingRange and Condition, and the agent's target is a pick inside it; an agent whose target has left the range refuses to start. Only the target is held to it, because a band is an alarm threshold and belongs outside. It also records the gap: market:aboutProperty occurs ONCE, so an agent can want exactly one thing, and the temperature and humidity this society senses feed nothing that can want anything.
* [self-review-is-a-capability](/decisions/self-review-is-a-capability.md) - Reviewing your own settings by shipped rules or by asking a model is one ability with two implementations, so it is a family and not kernel code. What grants it is latitude — an agent whose world leaves it room to move gets the means to use it — which is this capability's premise and not a rule about capabilities: the other three are granted by wiring. The mandate moved into the world, because a range is what an agent is allowed and only the pick inside it is its own.
* [bid-matching-is-a-capability](/decisions/bid-matching-is-a-capability.md) - Turning a lot and a set of bids into an allocation with prices left agent/auction.py and became market:BidMatchingCapability, pay-as-bid implemented and uniform-price declared beside it; the host states how it matches and the capability is derived from that. It is public and announced in the offer, because a bidder cannot bid well against terms it does not know. Saying it required fixing a conflation first: a market is the standing structure, an auction is the process that condenses inside it.
* [bid-matching-is-the-word](/decisions/bid-matching-is-the-word.md) - Three words were in circulation for one concept — matching, rule and format — all three in hosting.py alone. Matching wins on width: it covers the allocation rule and the payment rule, not how bidding proceeds. Format over-claims and means two incompatible things in the wild (a "Dutch auction" is descending-open to a theorist, uniform-price-sealed to a banker); rule collides with rules.ru. The qualifier is load-bearing — bare matching collides with matching a capability to a provider, which is what this project does everywhere else.
* [uniform-price-dissolves-the-uncontested-round](/decisions/uniform-price-dissolves-the-uncontested-round.md) - The second member of the matching family, which tested the claim that adding one moves nothing else — it did not. Every winner pays the lowest accepted bid, and the reserve is the floor rather than a fallback, so a round whose demand never reaches the lot clears at the reserve with no contested-or-not test anywhere. That makes #50 a choice of mechanism rather than a defect. Pay-as-bid rewards shading; uniform price rewards demand reduction; neither is free.
* [capability-packages](/decisions/capability-packages.md) - A package is one directory holding its own ontology, shapes, derivation rules, beliefs, code and namespace — found by looking, never listed. Capabilities reach each other through T-Box terms, never Python imports, so adding one is adding a directory and removing one is deleting it.
* [a-volume-can-be-older-than-the-vocabulary](/decisions/a-volume-can-be-older-than-the-vocabulary.md) - Beliefs are authored once and never touched again, so a belief base outlives the code that wrote it — and the namespace sweep moved 102 terms while both gates stayed green, one restart from silencing every deployed agent. Boot asks whether the vocabulary still declares what the store actually uses, which needs no version marker because the store already holds the evidence. Migration changes how a value is spelled and never which value it is, and it is a flag rather than a side effect, for the reason `rebirth` is one.
* [telemetry-is-a-mandatory-capability](/decisions/telemetry-is-a-mandatory-capability.md) - `ag:SelfReporting` claimed to be a capability directly above a comment saying it is granted to nobody, and it stayed in the kernel because grant-universality and implementation-uniformity were being treated as one question. Rule 2 asks only whether the HOW could differ — so a capability every agent holds is still one, and what it is not is optional. Reporting becomes a package granted by a rule and INSISTED ON by a shape; counting stays in the kernel, being the part that could not differ. A silent agent must stay distinguishable from a dead one, which is why it may never be conditional. What latitude grants is publishing which value an agent settled on, and that is #61.
* [every-term-in-its-own-house](/decisions/every-term-in-its-own-house.md) - The five packages still declaring into `ag:` took namespaces of their own, finishing what self-review-is-a-capability began when review's terms left the kernel FILE but kept the kernel's NAME. The finding is bigger than the move: a term is named seven ways here and six of them survive a rename by matching nothing — one had been doing so since PR #72, so the voucher half of a privacy test asserted nothing for four merged PRs while passing. There is a test for the class now. Eleven kernel terms are still not true of every agent, and they are named.
* [a-package-owns-its-namespace](/decisions/a-package-owns-its-namespace.md) - Every package declared an owl:Ontology IRI of its own and then put its terms in someone else's namespace, because store.PREFIXES was a kernel constant — a registry, in the tree whose claim is that adding a package edits nothing. The prefixes are now read off the ontologies that declare them; capabilities/market took market: and bid matching folded into it, because a directory is a package and not a capability. Three latent bugs only became visible once a second namespace existed.
* [an-unconfirmed-dose-is-not-a-delivered-one](/decisions/an-unconfirmed-dose-is-not-a-delivered-one.md) - The status channel a valve has always published on had no listener, so a dose that never happened looked exactly like one that did — REA had already named the gap, since an economic event is an OBSERVED flow. The deadline is derived: this dose's own open-seconds plus a stated grace, relative for the same reason perception's freshness is. An unconfirmed dose is counted but never re-sent, because the device refuses replays itself and over-watering is irreversible where a missed round is not. Getting there needed the runtime to stop handing a message to only the first module that wanted it.
* [settlement-speaks-rea](/decisions/settlement-speaks-rea.md) - There is no canonical auction ontology, but the settlement half is ordinary economic exchange and REA — ISO/IEC 15944-4, in RDF as ValueFlows — has modelled it for decades. Offer and bid are intents, the trade an agreement, the voucher a COMMITMENT rather than the claim we had been calling it, and actuation the event that fulfils it. The words are borrowed and the IRIs are not, because a hand-materialised RDFS closure has to cover every axiom it imports. Naming the one term we have no use for says settlement here is atomic.
* [a-round-is-an-iteration-not-the-auction](/decisions/a-round-is-an-iteration-not-the-auction.md) - Round meant two things in one file — the whole allocating process and one pass of bidding inside it — and the code has no loop, so the two coincide and nothing could fail. The round is the iteration, which is what multiple-round auction design means by the word; the auction is what condenses and dissolves. Splitting a quantity gives you lots, not rounds. The identifier is `auction_id` now, on all four payloads at once — offer, bid, voucher and signed command — because the key name is inside what the command's signatures cover.
* [a-role-needs-something-to-be-a-role-in](/decisions/a-role-needs-something-to-be-a-role-in.md) - Market positions stay predicates rather than becoming first-class roles. Both roles this project already models — a pin's and a user's — hang off a context object, and an auction deliberately has none, so a role here would be a second spelling of `market:hosts`. Measured: the predicate is already per-market, and an agent that hosts one and bids in another is handled by construction. Whether positions become roles and whether an auction becomes an object are the same question.
* [who-put-the-fact-there](/decisions/who-put-the-fact-there.md) - Public knowledge is five graphs split by who put the fact there: asserted, derived and entailed, for the vocabulary and for the world. An ordinary query still reads all five because they are its default graph — and a SELECT that names one reads only part, silently. Both engines now share one derivation instead of computing separately, which is how a live regression in the supplier's signing keys was found. Code names the CLASS and the store answers with the instances: a graph IRI is an instance, so `ag:PublicGraph` is the term and adding a public graph is a vocabulary edit that touches no Python.
* [one-graph-both-engines-read](/decisions/one-graph-both-engines-read.md) - Shapes inferred and the runtime did not, so a world could validate against a relationship the code would never observe — and six queries walked subclass paths by hand for twenty-five declared axioms. The entailments are materialised into the store at genesis; validation runs with inference off against that same graph, and a test fails if the two ever diverge.
* [a-procedure-belongs-to-whatever-performs-it](/decisions/a-procedure-belongs-to-whatever-performs-it.md) - Only sense modes were procedures, so a board's own doing was stated nowhere and a part's single message was explained as a transport economy rather than as one measurement. Each system now implements what it can perform, and the ESP32 became an `ssn:System` in order to be able to perform anything. The frame's first prediction was a live defect: one physical read was stamped three times, which #88's own evidence had recorded as two points 25 ms apart without noticing.

# Genesis

* [genesis](/decisions/genesis.md) - Sovereign narrates → LLM drafts → sovereign ratifies → infra writes structure + charters. Each output is a whole world (world/ holds several, one loaded at a time), and agents are born from it — the deployment is generated from the world, one container per agent. Amendable and versioned; structure mutable, history immutable.

# Seams (open on purpose)

* [standalone-clearing](/decisions/standalone-clearing.md) - The scarce side hosts the auction (host rotates with topology); the clearing validator stays invariant.
* [bids-as-unmet-demand](/decisions/bids-as-unmet-demand.md) - Bids reflect current unmet need, so multi-source decomposition stays possible.
* [where-the-belief-base-lives](/decisions/where-the-belief-base-lives.md) - A shared triplestore couples worlds that are meant to be independent: adding the 21st restarts the other 20. The world becomes TTL files an agent loads at start, beliefs live in a persistent store inside each agent, no shared store survives, and validation moves into the agent.
* [belief-base-isolation](/decisions/belief-base-isolation.md) - SUPERSEDED in mechanism by where-the-belief-base-lives, though its reasoning about why the graph is the write boundary still holds. Privacy was enforced by the store: per-graph ACLs behind per-agent credentials. It is now structural — there is no shared store to be let into.
* [roadmap](/decisions/roadmap.md) - What v1 is, and the v2/v3 extensions each seam unlocks.
