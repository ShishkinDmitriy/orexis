# Snapshot cases

A case holds a function to one claim: **given this store, leave that one.** Two files, in a
directory named for the function under test, beside the package's tests:

```
agent/<package>/tests/<function>/<case>.trig     the store BEFORE, hand-written
agent/<package>/tests/<function>/<case>.diff     what the function changes, generated
```

What the function must leave is `<case>.trig` with `<case>.diff` applied, compared quad by quad.
**The diff is the claim.** A reader diffs nothing by hand; the file IS the diff, and a review reads
it as one. The suites that use it today: `agent/planning/tests/` (`admit`, `derive_wants`,
`expand`, `lay_ground`, `plans`, `prepare_ground`, `reroot`, `scope_actions`, `take`, `weigh`),
`agent/sensing/tests/` (`received`, `missed`), `agent/prediction/tests/` (`predict`),
`agent/belief/tests/` (`revise`). The machinery is `agent/conftest.py`, reached by the
`snapshots` fixture: `stand_in` loads a case, `held_to_diff` holds a store to its diff,
`orphans_in` finds a diff whose case is gone. AGENTS.md's rule is the one that matters: **a case
is held to the whole store it leaves, never to a reading of it** — a behaviour change is a diff
regenerated by a flag and reviewed by eyes.

## Use namespaces

**Every IRI a case spells is a prefixed name**, never `<http://…>`, wherever a prefix exists. The
renderer abbreviates against the store's prefixes, longest namespace first, so a case written with
full IRIs will not match what the renderer writes and the diff fills with noise. Declare a case's
prefixes at its head as Turtle does, with the repo's spellings (`orexis:`, `planning:`, `execution:`,
`sensing:`, `prediction:`, `market:`, `hanoi:`, `courier:`, `climate:`, `actuation:`). A full IRI is
right in one place only: a term no loaded prefix covers, and if a package declares it the prefix is
missing from the case, not from the vocabulary.

**A full IRI in a REGENERATED diff is a finding, not formatting.** Where a local part will not
abbreviate — anything outside word characters, dots and hyphens — the renderer falls back to a full
IRI silently, which means something minted an IRI in a shape no prefix covers; the fix is the
code that mints it, never the diff. Grep before committing:

```bash
grep -n "<http" agent/<package>/tests/<function>/*.diff | grep -v "@prefix"
```

And look INSIDE literals: a set of triples held as a string in a triplestore is data modelled
as text, which nothing can query or abbreviate. It happened to a step's predicted facts, and the
fix was the representation (`knowledge/decisions/a-steps-prediction-is-two-graphs-it-names.md`),
never the case. A SPARQL or SHACL text is the legitimate case: it is a program.

## Canonical form, and why a case must already be in it

The renderer writes **one statement per line, flat**, subjects in rendered order, predicates and
objects sorted, `a` for `rdf:type`, bare numbers where Turtle has them, a blank node used once
inlined where it is used. Flat because Turtle's `;` and `,` make every line depend on the next, so
no diff over grouped Turtle can ever be minimal. **A hand-written case must already be in that
order**: `a` first, then predicates in order; a statement put where it reads best still passes and
leaves a hunk that only moves lines, the commonest noise in a review. When a diff gains a
reordering hunk, fix the CASE, not the diff.

## Regenerating

```bash
pytest agent/<package>/tests --update-snapshots
```

Rewrites every case's diff under that path from what the function actually left. The option is
registered in `agent/conftest.py`, so it is recognised wherever a suite under `agent/` is named;
`--bench-record` is the repo-root conftest's and unrelated. Then:

1. **`git diff` and read every regenerated diff.** It is a claim that behaviour changed on
   purpose. A line that surprises you means the change is wrong or the case is.
2. **A reordering hunk means the case is not canonical.** Fix the `.trig` and regenerate.
3. **Commit the regenerated diffs WITH the change that caused them**, never separately, and say
   in the commit what moved in them and why — "55 violation rows gain `planning:offending`" is a
   review; "snapshots updated" is not.

## When a case is red

The failure names the case, lists the quads left that the diff does not say and the quads the diff
says that were not left, and writes `<case>.actual.trig` **on a break and never otherwise**, the
store as it actually came out:

```bash
diff agent/<package>/tests/<function>/<case>.trig agent/<package>/tests/<function>/<case>.actual.trig
```

A green run leaves nothing behind, and `.gitignore` refuses the file either way. A stale diff —
one whose `.trig` changed after it was generated — is applied by line number with no fuzz and
asserts rather than guessing; regenerate it.

## Adding a case

1. Write `<case>.trig`: the whole store the function is handed, in canonical form, with a
   catalogue saying what each graph is, and a header comment saying what the case claims and
   where the clock stands. Comments are allowed — both sides strip them before diffing.
2. Run the case's test. It fails, and writes `<case>.actual.trig`.
3. Read the actual, and satisfy yourself it is what the function SHOULD leave.
4. `--update-snapshots` to write the diff, then read the diff as the reviewer will.
5. Break the guard on purpose once — strike the line of code the case exists for — and confirm
   the case goes red; a guard that has never failed is not a guard.

Never write a `.diff` by hand.

## What a case may not do

- **No wall clock.** The machinery pins one instant (`snapshots.NOW`); a case that reads the clock
  is not a case, and a function is handed its instant.
- **No hidden setup.** Everything the function reads is in the `.trig`, including the vocabulary it
  needs — a case that passes because a fixture quietly injected an axiom is testing the fixture.
- **No assertion inside a loop over something that may be empty.** The repo-root `conftest.py`
  fails a test that executed no assertion, which is the guard against exactly that.
